# 数据库迁移操作手册

## 一、日常迁移流程

### 1. 修改模型
编辑 `db/models.py`，完成字段/表的新增、修改、删除。

### 2. 运行迁移工具
```bash
python dev_tools/migration_db.py
```
按提示输入本次变更说明，例如 `add article table`。

### 3. 审查生成的脚本
工具会暂停，先打开 `alembic/versions/` 下最新生成的文件，按下方「二、常见场景改写清单」对照修改。

### 4. 确认应用
审查/修改完成后，回到终端输入 `y` 回车，工具会执行 `alembic upgrade head`。

如果想先放弃本次 upgrade，输入任意其它键取消。脚本会保留在 `alembic/versions/`，修改后运行 `alembic upgrade head` 继续应用。

## 二、常见场景改写清单

### 场景 1：列改名
**自动生成（错误）**
```python
op.drop_column('user', 'username')
op.add_column('user', sa.Column('user_name', sa.String(50)))
```
**改为**
```python
op.alter_column('user', 'username', new_column_name='user_name',
                existing_type=sa.String(50))
```
同步改 `downgrade()`：
```python
op.alter_column('user', 'user_name', new_column_name='username',
                existing_type=sa.String(50))
```

### 场景 2：类型扩容（String → Text、String(50) → String(200) 等）
**补全参数**
```python
op.alter_column('article', 'content',
                existing_type=sa.String(255),
                type_=sa.Text(),
                existing_nullable=False)
```

### 场景 3：类型收窄（Text → String(50)、String(200) → String(50) 等）
**在 alter_column 之前加数据清洗**
```python
op.execute("UPDATE article SET title = LEFT(title, 50) WHERE CHAR_LENGTH(title) > 50")
op.alter_column('article', 'title',
                existing_type=sa.Text(),
                type_=sa.String(50),
                existing_nullable=False)
```

### 场景 4：删列
**在 drop_column 之前加备份**
```python
op.execute("CREATE TABLE user_backup_20260419 AS SELECT * FROM user")
op.drop_column('user', 'legacy_field')
```

### 场景 5：新增非空列（表已有数据）
**分两步：先加可空列并回填，再改非空**
```python
op.add_column('article', sa.Column('status', sa.String(20), nullable=True))
op.execute("UPDATE article SET status = 'draft' WHERE status IS NULL")
op.alter_column('article', 'status',
                existing_type=sa.String(20),
                nullable=False)
```

### 场景 6：NOT NULL ↔ NULLABLE 切换
```python
op.alter_column('user', 'email',
                existing_type=sa.String(100),
                nullable=True)
```

### 场景 7：索引 / 唯一约束名变动
核对 `op.create_index` / `op.drop_index` 的名称与数据库实际名称一致，必要时手动指定 `name=` 参数。

## 三、回滚一个版本
```bash
alembic downgrade -1
```

回滚到指定版本：
```bash
alembic downgrade <revision_id>
```

---

## 四、查看状态

查看当前版本：
```bash
alembic current
```

查看版本历史：
```bash
alembic history
```

查看待应用的版本：
```bash
alembic heads
```

---

## 五、生产库操作前的演练

1. 从生产库导出 schema + 少量数据到测试库。
2. 在测试库运行 `alembic upgrade head`，确认成功。
3. 在测试库运行 `alembic downgrade -1`，确认能回滚。
4. 测试库验证通过后，再在生产库执行。

---

## 六、大表 ALTER（百万行以上）
不要直接用 Alembic，改用 `pt-online-schema-change` 或 `gh-ost` 执行在线 DDL，执行完成后用 `alembic stamp <revision_id>` 把版本号登记到 Alembic。
