# FastAPI 框架重构计划（AI 时代新定位）v2

## 背景

根据 `docs/AI 时代下的fastapi web 框架.md`，该框架定位为：

> **专为 AI 辅助编程、零配置的 FastAPI 脚手架**
> 用户只需用自然语言与 AI 提需求，AI 能顺着基础设施完成功能，不用担心配置与环境，只需专注于业务逻辑

重构前的框架保留了许多面向"人类程序员"的分层架构约定，复杂度高、AI 生成新模块时需跨多个文件操作。本次重构将按照 `docs/新时代框架重构指南.md` 进行三大方向的改造。

---

## 三大改造方向

### 方向一：异常处理与响应机制

**旧机制：** `Success`、`Error`、`ErrorCode` 封装类，API 层显式返回包装响应

**新机制：** 重写路由类（`APIRoute` 子类），在接口返回数据时**自动套上统一外壳**，无需手写中间件

| 项目 | 旧 | 新 |
|---|---|---|
| 成功响应 | `return Success(data)` | `return data`（原生 dict/Pydantic，路由类自动包装） |
| 业务异常 | `raise ApiException(ErrorCode.NOT_FOUND)` | `raise HTTPException(status_code=404, detail="...")` |
| 全局包装机制 | 无 | 自定义 `JsonRoute(APIRoute)` 重写 `get_route_handler` |

**实现方式：** 在 `exts/route.py` 中定义 `JsonRoute`，创建 `router` 时指定 `route_class=JsonRoute`，路由函数只需 `return data`，框架自动包装：

```python
# exts/route.py
class JsonRoute(APIRoute):
    def get_route_handler(self):
        original = super().get_route_handler()
        async def handler(request: Request) -> Response:
            resp = await original(request)
            # 如果已经是 JSONResponse 则解包再重包
            body = json.loads(resp.body)
            wrapped = {
                "success": True,
                "code": 200,
                "message": "操作成功",
                "data": body,
                "timestamp": int(time.time() * 1000),
            }
            return JSONResponse(content=wrapped)
        return handler
```

**响应格式保持不变**（前端兼容）：
```json
{ "success": true, "code": 200, "message": "操作成功", "data": {...}, "timestamp": 1678886400000 }
```
错误响应（由 exception_handler 处理）：
```json
{ "success": false, "code": 404, "message": "用户不存在", "data": null, "timestamp": 1678886400000 }
```

**改造内容：**
- **新建** `exts/route.py`：定义 `JsonRoute(APIRoute)` 自定义路由类
- `exts/exceptions/exception_handler.py`：移除 `ApiException` 处理器，`HTTPException`/`RequestValidationError`/`SQLAlchemyError` 继续保留，统一返回带 `success/code/message/data/timestamp` 的 JSON
- `exts/exceptions/api_exception.py`：**删除**
- `exts/exceptions/error_code.py`：**删除**（不再有自定义错误码体系，直接用 HTTP 标准状态码）
- `exts/responses/api_response.py`：**删除**（`Success`/`Error`/`ApiResponse` 全部废弃，由 `JsonRoute` 替代）

### 方向二：业务模块重构

**旧结构（分散在4个子目录）：**
```
apis/example/
├── api/         simple.py, user.py
├── services/    simple.py, user.py
├── repository/  simple.py, user.py
└── schemas/     simple.py, user.py
```

**新结构（物理合并到一个 routers 文件，彻底废弃 Repository/Service 类）：**
```
routers/
├── example.py    ← 设计单位模块
└── user.py       ← 用户模块
```

**核心原则：**
1. **CRUD 直接写在路由函数里**，不封装 Repository/Service 类。路由函数直接操作 `db_session`。
2. **只有极度复杂的跨模块计算**，才在文件底部写一个**普通纯函数**（无类封装）。

每个 `routers/xxx.py` 文件结构：
```python
from fastapi import APIRouter, Depends, HTTPException
from pydantic import BaseModel
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from exts.route import JsonRoute
from db.database import depends_get_db_session, depends_get_db_session_with_transaction
from db.models import XxxModel

# ======================== Schemas ========================
class XxxCreateRequest(BaseModel): ...
class XxxResponse(BaseModel): ...

# ======================== Router ========================
router = APIRouter(prefix="/api", tags=["Xxx模块"], route_class=JsonRoute)

@router.post("/xxx")
async def create_xxx(
    payload: XxxCreateRequest,
    db: AsyncSession = Depends(depends_get_db_session_with_transaction),
):
    # 直接在这里查询和操作数据库，无 Service 层转发
    result = await db.execute(select(XxxModel).where(XxxModel.name == payload.name))
    if result.scalars().first():
        raise HTTPException(status_code=409, detail="已存在")
    obj = XxxModel(**payload.model_dump())
    db.add(obj)
    await db.flush()
    await db.refresh(obj)
    return XxxResponse.model_validate(obj)

# ======================== 复杂纯函数（仅在必要时添加）========================
# async def _calculate_something_complex(db, ...): ...
```

**改造内容：**
- 新建 `routers/` 目录
- 新建 `routers/example.py`（设计单位相关，CRUD 直接在路由函数内完成）
- 新建 `routers/user.py`（用户注册/登录/获取信息，加密和 JWT 直接在路由函数内调用）
- 更新 `app.py`：直接 include `routers/` 下各路由，移除 `AppFactory` 复杂注册逻辑
- 删除 `apis/` 整个目录
- `app_factory.py`：大幅精简，移除多子应用挂载

### 方向三：测试改造

**旧机制：** `conftest.py` + `Factory` + 依赖注入 override + 单元测试 Mock

**新机制：** 黑盒集成测试，用 `httpx` 请求真实接口，校验返回结果

新测试脚本特点：
- **无 conftest** 复杂配置
- **无 Factory**，直接在测试脚本里构造 payload
- **无依赖注入 override**
- 使用 httpx 对运行中的服务器发请求（或使用 `TestClient`）
- 校验 HTTP 状态码和响应体字段

**改造内容：**
- 删除 `tests/factories.py`
- 删除 `tests/unit/`（单元测试）
- 删除 `tests/integration/`（旧集成测试）
- 新建 `tests/test_example.py`：简单的黑盒测试脚本
- 新建 `tests/test_user.py`：用户接口黑盒测试
- `pytest.ini`：简化配置

### 方向四：更新 README.md 与文档

- 重写 `README.md` 以体现新的 AI 时代定位
- 更新架构说明，反映新的 `routers/` 单文件模块模式
- 移除旧的"分层架构"描述
